# ECO-150 — Lote D del censo E3: reconciliar los charts (fork del dashboard → DS)

Strategy: design-propagation

## Resumen

Cuarto lote del censo 1-a-1 (ECO-146 / E3), y el primero con **decisión de diseño** (no dedup mecánico).
El dashboard había **forkeado** los charts presentacionales del DS y divergido. Reconciliación a una sola
presentación gobernada.

- **Decisión del operador — color de las series de datos = tokens de chart, NO accent.** Los charts del DS
  pintaban los datos con `accent`/`accent-2` (verde de marca); los forks del dashboard ya usaban
  `chart-1`/`chart-2` (los primitivos de datos de ECO-145). `accent` es la **marca**, no un color de dato →
  se arregla el DS a `chart-1`/`chart-2`/`content-primary`. Así el dashboard (que ya usa chart-*) **no
  cambia sus colores de datos**; solo se alinea el catálogo del DS.
- **TotalUsersChart**: ambos eran presentacionales estáticos (mismos datos mock, 2 líneas). El fork del
  dashboard era una copia stale → **borrado**; el dashboard consume el `TotalUsersChart` del DS por `em-ui`
  (`app/dashboard/page` + `ComponentShowcase`, ambos `<TotalUsersChart />` sin props).
- **UserRoleChart**: es el donut **conectado** (fetch de conteos por rol) que **duplicaba** el render del
  `DoughnutChart` del DS. Refactor: mantiene el fetch + estados de carga/error, y en éxito **delega** en
  `<DoughnutChart data={…} />` — una sola presentación de donut, sin drift. Los fills por rol
  (chart-1/chart-2/content-primary) ya coinciden con el `DEFAULT_DATA` reconciliado del DS.

Nota: los tokens auxiliares (ticks/leyenda) del DS son semánticos limpios (`content-tertiary`,
`content-secondary`) frente a los alphas ad-hoc del fork (`content-primary/0.5`, `/tertiary`) — el gridline
es idéntico; el único delta posible es texto auxiliar levemente más oscuro. El **Dashboard VRT** es el
árbitro: si marca algo, es un refinamiento a revisar por el operador (no un cambio de datos).

## Decisiones fijadas (operador)

- **Series de datos con tokens de chart, no accent** (elegido en la bifurcación presentada): semánticamente
  correcto y sin mover los colores de datos del dashboard. Alinea el DS al dashboard (correcto), como la
  resolución del drift de em-ui-tokens (ECO-115).
- **Producto (surfaced):** el chart "Total Users" muestra **datos mock estáticos** en ambas copias — cablearlo
  a datos reales es un ticket de producto aparte, fuera de este dedup.

## Acceptance Criteria

- Los charts del DS (`TotalUsersChart`, `DoughnutChart`) usan `chart-1`/`chart-2`/`content-primary` para los
  datos (0 `accent`/`accent-2` en series de datos); `check-raw-color`/`check-contrast`/`check-brand-contrast`
  verdes.
- El fork `components/dashboard/TotalUsersChart.tsx` queda borrado; sus 2 consumidores usan
  `@/components/ui/TotalUsersChart` (copia gobernada); 0 imports al fork.
- `UserRoleChart` delega su donut en `@/components/ui/DoughnutChart` (mantiene fetch + carga/error); no
  duplica el render de recharts.
- `check-component-drift` verde (copias em-ui idénticas a la fuente); dashboard typechea, buildea y su suite
  pasa (22/22).
- **Dashboard VRT**: los colores/estructura de datos no cambian. Cualquier delta que marque el VRT (texto
  auxiliar) se revisa con el operador antes de mergear (cadencia: cambio visual = su criterio).

## Alignment

- **Censo de normalización (design-propagation, backward)**: colapsa el fork drifteado de charts — el "riesgo
  caliente" que el censo señaló — a una sola presentación gobernada.
- **Tokens correctos (ECO-145)**: `accent` es marca; los datos van con los primitivos `chart-*` dedicados.
  Esta reconciliación corrige el uso semántico en el DS.
- **Distribución por copia gobernada (ADR-006/007)**: los charts viajan por `em-ui add` (pull); UserRoleChart
  consume el DoughnutChart gobernado.
- **No-goals**: no re-diseñar los charts (misma presentación, solo el color de datos correcto + dedup del
  render); no cablear datos reales del "Total Users" (ticket de producto aparte).
