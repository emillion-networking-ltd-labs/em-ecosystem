# ECO-210 — Rename tokens de borde a `line-*` (legibilidad + rol explícito del control)

Strategy: design-tokens

## Contexto

Los 4 tokens de color de borde se leían **mal** y tenían **semántica turbia** (lo señaló el operador):

- **Tartamudeo** `border border-border-strong` — la palabra "border" sale 3 veces (el grosor `border`, el prefijo de
  color `border-`, y el nombre del token `border-strong`). Nace de que el token lleva "border" en el nombre y se usa
  como utility de color de borde.
- **Ejes mezclados**: `subtle < default < strong` es una escala de PESO, pero `components` es un ROL (el borde de los
  controles interactivos, atado a la NORMA de contraste 3:1) colado en la misma familia. `components` no dice qué es.
- **`default` no es el default**: el más usado (de facto) era `strong` (204 usos) — el nombre mentía.

## Decisión (acordada con el operador)

Sacar "border" del nombre (mata el tartamudeo) + nombrar el rol:

| antes | ahora | valor (intacto) |
|---|---|---|
| `--border-subtle` / `border-border-subtle` | `--line-subtle` / `border-line-subtle` | negro 0.03 |
| `--border-default` / `border-border-default` | `--line-default` / `border-line-default` | negro 0.08 |
| `--border-strong` / `border-border-strong` | `--line-strong` / `border-line-strong` | negro 0.14 |
| `--border-components` / `border-border-components` | `--line-control` / `border-line-control` | negro 0.42 (NORMA 3:1) |

`line` = la línea del borde; `control` = el borde de los controles interactivos (el de la NORMA). Se lee
`border border-line-strong` → "border" una vez (el grosor) y el color limpio. **Solo cambian los nombres, no los
valores** (la NORMA 3:1 sigue validándose: `line-control` = 3.03:1 sobre surface-primary).

## Alcance (rename fleet-wide, mecánico)

- `tokens.css`: definiciones (`:root`/`.dark`/`.light`) + alias `@theme` (`--color-line-*`) + `@utility card*`.
- **~339 usos** de la utility en la flota (DS components/sections/stories/tests/fixtures + dashboard + satélite).
- Gate `check-contrast.mjs`: los pares hardcodeaban `border-components/strong/default` → renombrados a
  `line-control/strong/default`. **Crítico**: el gate SALTA en silencio un token ausente (no lo valida) — si no se
  actualiza, la NORMA 3:1 dejaría de comprobarse sin avisar.
- `TokenInspector.tsx` (dashboard): los `cssVar: "--border-*"` (strings) → `--line-*`.
- Propagación: `em-ui init` (token layer) + `em-ui update` por copia. Las 4 copias `@em-ui-adapted` del satélite
  (Button/Select/BeforeAfterSlider/Divider) se renombraron preservando su adaptación (el rename es ortogonal a ella).
- `.em-ui/base` (bases congeladas) NO se toca — son snapshots históricos por-sha.

## No-goals

- NO cambiar valores (es solo rename; el afinado de opacidades es otro asunto).
- NO renombrar el eje de peso (`subtle/default/strong`) — se mantiene; solo `components`→`control` + quitar "border".

## Acceptance Criteria

- Cero `border-border-*` ni `--border-{subtle,default,strong,components}` en código vivo (`.em-ui/base` exento).
- `check-contrast` valida `line-control` a 3:1 (NORMA intacta); `coverage` + `governance` verdes (sin drift).
- Suite (`vitest run`) verde; fixtures de fidelidad renombrados en paralelo.
- Copias em-ui reconciliadas (4 adapted preservadas); token layer propagado a dashboard + satélite.

## Alignment

design-tokens (ADR-033): los colores de línea/borde ∈ MARCA (el satélite re-apunta `--line-*` en `[data-brand]`;
`line-control` es además NORMA a11y). No cambia el modelo — afila la **legibilidad y la semántica** de la etiqueta,
prerequisito de calidad antes de la migración pieza-por-pieza (las 50 piezas migran ya sobre nombres limpios).
