# ECO-203 — Atenuación `/NN` a tokens semánticos + gate universal (paso 2 design-tokens)

Strategy: design-tokens

## Contexto

Paso 2 de la ejecución design-tokens (ECO-200 / ADR-033). La atenuación (alpha ad-hoc con el modificador de opacidad
de Tailwind `text-content-primary/75`, `/50`…) es un **número mágico**: sin fuente única, gobernada solo por
contraste, no por consistencia. En el modelo de 4 categorías la atenuación es **ESTRUCTURA-DS** (tokenizada +
bloqueada) → aplica a **TODAS** las piezas (core y decorative); **no tiene escape-hatch** (el escape-hatch del modelo
es para layout/spacing, no para velos).

Grounding (`design-system/components` + `sections`): **68** `/NN` sobre tokens semánticos (64 core · 1 decorative · 3
secciones) + **15** crudos `black/white/NN` (scrims). Hallazgo: el `/NN` **siempre** arranca de `content-primary` o
de un feedback pleno — nunca de secondary/tertiary → es **un token atenuado escrito a mano**.

## Regla (acordada con el operador)

**Un token se justifica por uso MÚLTIPLE; el `/NN` de uso único se PLIEGA a un token existente por rol** — no se
inventa tono nuevo (el propósito de tokenizar es precisamente **no inventar tonos**). Cada `/NN` cae en un **peldaño
que YA existe y está registrado**, elegido por el USO.

## Mapeo (a tokens existentes)

| `/NN` | usos | → token |
|---|---|---|
| `content-primary/75` | 46 | `content-secondary` (control/texto interactivo apagado) |
| `content-primary/50` | 15 | `content-tertiary` (iconos apagados; consolida la escala) |
| `content-primary/30` | 5 | `content-placeholder` (empty-state/hint; 0.30 exacto) |
| `/25` (Ripple, relleno) | **1** | pliega a `surface-*`/`placeholder` por rol |
| `/20` (gridline, línea) | **1** | pliega a `border-*` por rol |
| `success/30` (borde) | **1** | pliega a borde de feedback existente / `success` |
| scrims `black/white/NN` | 15 | `--overlay` existente (+ nivel solo si ninguno encaja) |
| `error/75` | 11 | **único candidato a token nuevo `error-muted`** (multiplicidad lo justifica y no hay peldaño feedback atenuado) — se confirma con el visual antes de crearlo |

**Matiz theme:** `/75`/`/50` son *theme-blind* (alpha fijo); los tokens son *theme-aware* → en **light** aclaran un
pelín. Es el arreglo **correcto** (theme-aware, es el bug que la estrategia ataca) pero **VISIBLE** → revisión visual
del operador en Storybook light/dark, por tanda.

## Enforcement

Gate **`check-attenuation-usage`** (nuevo): **UNIVERSAL** — todo `/NN` sobre una clase de color (token o crudo) debe
resolver a un token; **sin exención de tier** (la atenuación es ESTRUCTURA-DS). **Ratchet** (baseline ≈ 68 → 0 al
drenar por tandas), helpers de `_ratchet.mjs` (como `check-typography-tokens`). **Registrado** en
`enforcement/protected-dimensions.json` (ADR-031, lo exige el meta-gate `check-protected-dimensions`). Cableado en la
cadena `coverage`.

## Tandas (cada una con revisión visual del operador)

1. `/75` → `content-secondary` (46).
2. `/50` → `content-tertiary` (15).
3. `/30` → `content-placeholder` (5) + singletons (`/25`, `/20`, `success/30`) pliegan a existente.
4. `error/75` → `error-muted` (si el visual lo justifica) o mapeo.
5. scrims → `--overlay`.
6. Gate + reconciliar copias em-ui + verificar.

## No-goals

- **NO inventar tonos nuevos** salvo `error-muted` (justificado por 11 usos + aprobado con el visual).
- **NO** tocar valores intrínsecos de un efecto decorative (`color-mix` del shimmer, etc.) — no son atenuación `/NN`.
- **NO** endurecer otras dimensiones (radius/shadow/border van en pasos siguientes).

## Acceptance Criteria

- **Cero `/NN`** sobre tokens/crudos en `components` (y el scope acordado de `sections`), salvo escapes declarados.
- `check-attenuation-usage` corre en `coverage`, verde; probado que caza un `/NN` nuevo; registrado en
  `protected-dimensions.json`.
- Copias em-ui reconciliadas; `governance`/drift verde.
- Suite (`vitest run`) + `coverage` verdes. Revisión visual del operador OK por tanda.

## Alignment

design-tokens (ECO-200 / ADR-033): implementa la dimensión **ATENUACIÓN** de ESTRUCTURA-DS — fuente única +
consistencia (no solo contraste). Es el **paso 2** del orden de ejecución. Aplica la regla "multiplicidad justifica
el token; singleton se pliega a lo existente", y el eje `@ds-tier` de ECO-202 (aunque la atenuación es universal, no
tier-exenta).
