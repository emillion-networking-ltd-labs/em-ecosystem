# ECO-195 — Normalizar el import de animación a `motion/react` + gate (design-enforcement)

Strategy: design-enforcement

## Contexto

Cabo de **Fase 0** (cimientos) del roadmap del DS: la librería de animación se importaba con **dos nombres para la
misma lib** — `motion/react` (×8 en el DS) Y `framer-motion` (×2 en el DS: Toast, ToastContainer), y el dashboard
arrastraba `framer-motion` en 5 imports (2 copias em-ui + 3 propios) + su package.json (v12.42, drift de versión con
el DS 12.38) **sin** `motion`. Es la "version-soup de fábrica" que design-distribution.md:58 marcó como saneamiento
previo acoplado. El campo `dependencies` del registry se **auto-deriva** de los imports (build-registry.mjs) → al
normalizar el import, el registry pasa de `framer-motion` a `motion` solo.

Séptima dimensión de piso de design-enforcement (ADR-031), receta migrar-stragglers → enforce: una vez la flota está
en un solo nombre, un gate impide que vuelva a colarse el otro. Responde al principio del operador "se quedan cosas
sueltas y nadie las detecta": tras normalizar, la dup queda **detectada para siempre**.

## Alcance

- **Normalizar TODA la flota** `framer-motion` → `motion/react` (mismos símbolos `motion`/`AnimatePresence`): DS
  (Toast, ToastContainer) + dashboard (PasskeyManager, TrustedDevices, ComponentShowcase + las 2 copias em-ui
  Toast/ToastContainer, que quedan byte-idénticas al DS). Instalar `motion` en el dashboard, soltar `framer-motion`
  de **ambos** package.json. Rebuild del registry (el campo `dependencies` pasa a `motion`). Actualizar las 2
  referencias-string al nombre del paquete (component-registry, ComponentShowcase specs).
- **`check-animation-import.mjs`** — caza `from "framer-motion"` (import). Scope **fleet** (DS + dashboard +
  satélites, excluyendo `node_modules`/build). Escape `animation-ok`. Mode **enforce** (flota a 0 tras normalizar →
  lock preventivo). Registrado en el manifiesto (dimensión #7) + cableado en `coverage` + `governance`.
- Test `animation-import`. Meta-gate: 7 dimensiones.

## No-goals

- No tocar la escala/versión de `motion` más allá de converger el dashboard a la declarada por el registry.
- No migrar otras APIs de animación (keyframes/easings) — solo el NOMBRE del import.

## Acceptance Criteria

- 0 imports `from "framer-motion"` en toda la flota; el gate pasa; falla con un `from "framer-motion"` nuevo; respeta
  `animation-ok`.
- `framer-motion` fuera de ambos package.json; `motion` presente en ambos; registry rebuild sin `framer-motion`.
- Drift verde (copias em-ui Toast reconciliadas byte-idénticas), lint + tests del dashboard y del DS verdes.
- Registrado + cableado; meta-gate verde (7 dimensiones).

## Alignment

Ejecuta design-enforcement (ADR-031): séptima dimensión de piso (nombre del import de animación), misma receta
migrar → enforce con precisión por-dimensión. Cierra el cabo de animación de **Fase 0** del roadmap del DS
([[eco-ds-roadmap]]); saneamiento acoplado que design-distribution.md:58 dejó pendiente.
