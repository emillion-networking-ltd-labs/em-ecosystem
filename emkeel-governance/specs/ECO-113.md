# ECO-113 — Charts: paleta a tokens de marca (sin hex crudo) + tema global (retirar forceDark)

Strategy: satellite-design

## Resumen
Los tres charts del design-system pintaban su paleta con **colores genéricos crudos** (`#a0bce8`, `#6be6d3`,
`#1c1c1c`/`#f5f5f5`) en vez de los **tokens de marca del sistema**, y `TotalUsersChart`/`DoughnutChart` llevaban
un flag `forceDark` por-instancia para simular el tema. La revisión visual 1:1 del catálogo (ECO-111) destapó
ambas deudas y las difirió a este ticket. Se corrigen las tres piezas:

- **DoughnutChart** — los rellenos de slice pasan a tokens como variables CSS: USER → `--color-accent`,
  ADMIN → `--color-accent-2`, SUPERADMIN → `--color-content-primary` (que ya se invierte con el tema).
  Se **elimina el prop `forceDark`** y el helper `defaultData(isDark)` → una constante `DEFAULT_DATA`.
- **TotalUsersChart** — línea principal → `--color-content-primary`, comparación ("Last year") → `--color-accent`,
  ticks → `--color-content-tertiary`, grid → `--border-strong`. Se **eliminan `useTheme`, `useMemo` y `forceDark`**;
  la paleta es una constante `COLORS` de variables CSS. La leyenda "Last year" usa `bg-accent`.
- **SpeedometerChart** — ya usaba clases de tema (sin hex). Se **centra verticalmente el gauge**: `h`/`cy` por
  tamaño estaban calculados dejando una banda vacía grande arriba; se recalculan para un margen simétrico
  (~6px arriba/abajo) ajustando `viewBox`/`h`/`cy` en el SVG (no desde la story).

## Decisiones fijadas (operador)
- **Paleta a tokens de marca, cero hex crudo:** accent / accent-2 / content-* — el accent verde de hoy es el
  placeholder del sistema; los charts adoptan el vocabulario de tokens, no colores sueltos.
- **El tema es GLOBAL, no un flag por-instancia.** `forceDark` era un override JS redundante: el catálogo ya
  renderiza light/dark en paralelo envolviendo cada panel en un div temado (`.light` / `.dark`), y ese wrapper
  fija los tokens vía variables CSS. Si el chart lee color de `var(--color-…)`, sigue el tema por la cascada CSS
  — sin `useTheme`, sin prop. recharts escribe stroke/fill directo al atributo SVG, que resuelve el `var()` del
  wrapper. Se conserva la vista light/dark en paralelo del catálogo (los paneles siguen temados).
- **Centrar el gauge desde el SVG** (viewBox/alto/cy), no parcheando la story.
- **No tocar el diseño/API de los primitivos ajenos** ni valores de `tokens.css`; solo se consumen tokens ya
  existentes (`--color-accent`, `--color-accent-2`, `--color-content-primary`, `--color-content-tertiary`,
  `--border-strong`).

## Acceptance Criteria
1. `DoughnutChart`, `TotalUsersChart` y `SpeedometerChart` no contienen **ningún hex/rgb crudo**: todo color
   sale de tokens de marca (accent / accent-2 / content-* / border) como variables CSS o clases utilitarias.
2. Light/dark del catálogo se ve correcto en los tres charts (los slices/líneas siguen el tema por la cascada),
   y la vista light/dark en paralelo del catálogo sigue funcionando.
3. **`forceDark` eliminado** de `DoughnutChart` y `TotalUsersChart` (y con él `useTheme`/`useMemo` en el line
   chart); el tema se deriva del wrapper temado, no de un prop.
4. El gauge del `SpeedometerChart` queda **verticalmente centrado** en su SVG (margen simétrico arriba/abajo)
   en los tres tamaños (sm/md/lg); el ajuste vive en `speedoSizes` (viewBox/h/cy), no en la story.
5. Las stories de charts reflejan la paleta por tokens (se retira el TODO "→ brand tokens in ECO-113").
6. Aislamiento: no se toca `nexacore-api/`; el core `tokens.css` no cambia valores. Lint y tests del dashboard
   verdes; `dup:check` sin duplicación nueva.
7. Gates verdes (`Strategy: satellite-design`, ticket ECO-113), Security Pipeline (sin secretos).

## Alignment
Sirve al pilar de `satellite-design.md`: el theming por tokens (cero colores crudos) es una **condición
innegociable** de la estrategia — los componentes del design-system deben vestirse con el vocabulario de marca
(accent/content/surface/border), no con colores sueltos que no siguen el tema ni la marca. Este ticket lleva los
charts a esa forma correcta y, de paso, hace el mecanismo de tema **coherente**: un solo modelo (tema global vía
la cascada CSS del wrapper temado) en vez de un flag JS por-instancia, que es el mismo principio de adherencia al
tema que rige el resto del catálogo.
