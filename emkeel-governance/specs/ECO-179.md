# ECO-179 — Input: migrar sus iconos a `<Icon>` (rollout del sistema de tamaño)

Strategy: design-system-quality

## Contexto

Primer paso del rollout del sistema de icono (ECO-178): migrar los usos de Input a `<Icon>` para que el tamaño
salga de la escala registrada, no de `size={16}` a pelo. Input tiene dos iconos: el ojo de password (dentro de
IconButton) y el `TriangleAlert` del texto de error.

## Alcance

- Ojo de password (`Eye`/`EyeOff`) → `<Icon size="md">` (16px, **sin cambio** — es la convención del icon-button).
- Icono de error (`TriangleAlert`) → `<Icon size="sm">` (**16→14px**): el texto de error es `text-caption` = **12px**,
  y un icono de 16 quedaba desproporcionado (33% mayor que el texto). `sm` (14) es proporcional. **Cambio visual
  menor, intencional** (mejora la proporción; lo flagueó el operador).
- Input pasa a componer `Icon` (registryDependencies += Icon); dashboard + satélite re-pullan el cierre sin drift.

## No-goals

- No toca los demás usos del rollout (Avatar, IconButton/Button, consumidores, gate) — van en sus tandas.

## Acceptance Criteria

- Los iconos de Input salen de la escala vía `<Icon>` (sin `size={16}` a pelo).
- El icono de error a `sm` (14px), proporcional al caption (12px); el ojo a `md` (16px, sin cambio).
- `input-fidelity` (la caja) sigue verde; composition-class + tsc + anti-drift verdes.

## Alignment

- **Rollout del sistema de icono:** aplica la escala registrada por pieza, con RECONCILIACIÓN (el error se ajusta a
  la proporción del texto, no se copia el 16 a ciegas). Relacionado con [[eco-icon-size-system-debt]].
