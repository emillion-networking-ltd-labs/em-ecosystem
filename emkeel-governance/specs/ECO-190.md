# ECO-190 — design-enforcement: esqueleto (manifiesto de dimensiones protegidas + meta-gate + ratchet)

Strategy: design-enforcement

## Contexto

Primer paso de ejecución de la estrategia **design-enforcement** (ADR-031): antes de la familia de gates, el
**andamiaje** que hace la meta-regla mecánica en vez de aspiracional — el manifiesto de dimensiones protegidas, el
meta-gate que lo vigila, y el ratchet para desplegar gates sobre corpus sucio sin big-bang.

## Alcance

- **`design-system/enforcement/protected-dimensions.json`** — el manifiesto. Cada dimensión de fuente única que no
  debe escribirse a mano declara `{ dimension, piece, gate, scope, escape, mode, ceiling, note }`. Sembrado con las
  2 que ya existen: **icon** (gate `check-icon-usage.mjs`, scope `ds`, escape `icon-ok`, mode `enforce`) y **color**
  (gate `check-raw-color.mjs`, scope `fleet`, escape `raw-color-ok`, mode `enforce`).
- **`design-system/scripts/check-protected-dimensions.mjs`** — el **meta-gate**: verifica manifiesto ↔ gates en
  AMBOS sentidos. FORWARD: cada dimensión del manifiesto tiene su gate (fichero existe) y está cableado en el script
  `coverage`. REVERSE: todo gate `check-*-usage.mjs` (la convención de nombre de un gate-de-dimensión) está
  registrado en el manifiesto. Valida campos requeridos + `scope` ∈ {ds, consumer-minus-primitives, fleet} + `mode`
  ∈ {report, ratchet, enforce}. Cableado en `coverage`.
- **`design-system/scripts/_ratchet.mjs`** — helper del modo ratchet: `ratchetCheck` (falla si las violaciones
  SUBEN vs el baseline) + `nextBaseline` (el baseline solo DECRECE). Modelo espejo de ESLint bulk-suppressions;
  lo usarán los gates de dimensión que nazcan en modo ratchet (el primero, spinner).
- **Test** `tests/protected-dimensions.test.ts` — funciones puras (forward/reverse/campos + ratchet) + guard
  permanente del manifiesto real.

## No-goals

- Los gates de dimensión en sí (spinner, HTML-crudo, tipografía…) — van uno por ticket a partir de aquí, cada uno
  añadiéndose al manifiesto.
- El scope satélite del gate de icono / el techo operativo (censo) — pasos posteriores del rollout.

## Acceptance Criteria

- El meta-gate pasa con el manifiesto sembrado (icon + color) y está en `coverage`.
- El meta-gate FALLA si: una dimensión no tiene su gate (o no está cableado), un gate `check-*-usage` no está
  registrado, o falta un campo / scope|mode inválido.
- El ratchet: `ratchetCheck` falla solo al subir; `nextBaseline` nunca sube.
- Tests verdes; el manifiesto real está sano.

## Alignment

Ejecuta la estrategia **design-enforcement** (ADR-031): construye la META-REGLA operativa. El manifiesto + meta-gate
es lo que garantiza que ninguna dimensión (presente o futura) se quede sin candado y que el manifiesto no drifte de
los gates reales — el mecanismo que corta el ciclo de reconstrucción. Relacionado con [[eco-ds-roadmap]].
