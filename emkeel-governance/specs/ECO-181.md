# ECO-181 — Composición: deps estructurales vs helper + reuso de icono contextual

Strategy: design-system-quality

## Contexto

Con el rollout del icono, casi toda pieza gana `Icon` en `registryDependencies`. Si "tener dep = Composite", la
distinción Simple/Composite se vuelve inútil. Y un banner blanket "Uses Icon…" en una pieza es engañoso (muestra
solo los helpers, no todo lo que usa — p.ej. Input usa también IconButton).

## Alcance

- **`_deps-class.mjs`** (fuente única): distingue deps **ESTRUCTURALES** (la esencia — SegmentedControl → Button)
  de **HELPERS** transversales (`Icon`, `SpinnerInfinity/Circle/Ring`).
- **Norma `check-composition-class`** afilada: Composite = tiene deps **estructurales** (no basta con `[Icon]`) →
  el rollout del icono no mis-clasifica.
- **Banner "Composed of"** (preview.tsx): muestra solo la composición **estructural** (filtra helpers); sigue
  siendo solo para `Composite/`. **Se quita el banner "Uses" blanket** (era engañoso).
- **Reuso de icono CONTEXTUAL**: en la story donde el icono es la feature se anota (p.ej. `Left icon · uses Search`),
  solo para el caso del icono — no una etiqueta global. Las stories usan `<Icon>` (dogfooding).

## No-goals

- No documenta el reuso de helpers como etiqueta global (bajo valor + engañoso). El registry ya lo registra.

## Acceptance Criteria

- `Composite/*` requiere deps estructurales (un Composite con solo `[Icon]` falla la norma).
- El banner "Composed of" lista solo estructurales; sin banner "Uses".
- La anotación contextual aparece solo en la story de la feature de icono; coverage/story-norm/tsc verdes.

## Alignment

- **Modelo de composición honesto:** Simple/Composite por esencia (estructural), el icono es un helper. El catálogo
  muestra la composición estructural (prominente) y el uso de un icono concreto donde toca (contextual), sin ruido.
  Relacionado con [[eco-icon-size-system-debt]].
