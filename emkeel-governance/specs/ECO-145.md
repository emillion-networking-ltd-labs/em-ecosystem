# ECO-145 — design-propagation Fase 1 (E2): `check-raw-color` (gate) + capa de tokens primitivos + tokenización total

Strategy: design-propagation

## Resumen

Segundo entregable de la Fase 1 de **design-propagation** (aprobada, ADR-028): cerrar la clase de error
**grep-catchable** del estándar — un elemento pinta con un **valor crudo de color** (hex, `rgb/hsl`, arbitrary
Tailwind `-[#…]`, o una clase de paleta cruda tipo `text-slate-500`) en vez del vocabulario de **tokens**. El
color crudo no sigue el tema, no respeta la marca y escapa a `check-contrast`/`check-brand-contrast`.

Decisión del operador: **no arrastrar deuda** — no un gate advisory permanente, sino tokenizar TODO ahora y
dejar el gate **bloqueante**. Y la forma profesional de "todo tokenizado" es la **capa de tokens primitivos**
(option tokens): valores con nombre, **fijos** (no theme-aware, se definen una vez), para lo que no es semántico
(negro/blanco base, marca de terceros, datos de chart, estéticas theme-independent). Así todo referencia un
token → un cambio desde la base propaga, y nada se rompe (un primitivo no flipa con el tema, a diferencia de un
token semántico).

Piezas:

- **`check-raw-color.mjs`** (gate nuevo, bloqueante, cableado a `coverage` + `governance`): escanea DS +
  código de cada consumidor (barrido total) por valores crudos de color. **Exime** los ficheros que DEFINEN
  tokens (`tokens.css`, `brand.template.css`, `em-ui-tokens/brand.css`, `design-tokens.ts`, herramientas de dev
  que muestran valores — TokenInspector/ComponentShowcase) y **las líneas que DEFINEN un custom property**
  (`--x: valor` = fuente del token). Ignora comentarios y `rgb(var(--token))` (uso de token con alpha). Escape
  por línea: `raw-color-ok: <razón>`.
- **Capa de primitivos** en `tokens.css` (ECO-145): `--color-black`/`--color-white` (neutros base), marca de
  tercero reutilizable `--color-brand-google-{blue,green,yellow,red}`, y datos de chart `--color-chart-1/2`.
  Fijos, no re-declarados por tema. Propagados a los consumidores.
- **Tokenización total** de la deuda genuina (sin cambio visual — todo mapea 1:1 al valor actual del token):
  - Charts (`UserRoleChart`, `TotalUsersChart`): color por serie → `chart-1/2` + `content-primary`; se retira
    `forceDark`/`useTheme`/`useMemo` (ECO-113: el tema es global, no un flag por-instancia; el wrapper `.dark`
    del showcase lo maneja).
  - Satélite: oro del Hero → `accent-light`; splash → `--color-black`/`--color-white`; card de periódico de
    `PortfolioPreview` → primitivos **locales del satélite** (`--paper`/`--paper-ink`/`--paper-gold`, fijos:
    la card es siempre papel crema + tinta + oro, theme-independent → no van al DS compartido).
  - Google (logo OAuth) → `--color-brand-google-*`. Efecto AuroraBackground → `--color-black/white`.
- **Declarados `raw-color-ok`** (auditado, no es deuda arrastrada): página de crash (`.global-error-*` +
  `global-error.tsx` — self-contained, no puede depender de que el CSS de tokens cargue), fixtures de story
  (placeholders SVG), doc-strings de `*Specs` y prosa que ENSEÑA la norma.

## Decisiones fijadas (operador)

- **Tokenizar TODO vía la capa de primitivos** (no advisory, no arrastrar): cada color con nombre → un token →
  cambiable desde la base + reutilizable + uniforme. El gate queda **bloqueante**.
- **Cada token = UN significado**: no reutilizar un token semántico (`--color-surface-qr`, que es del QR) como
  "blanco genérico" → primitivos dedicados (`--color-black`/`--color-white`).
- **Primitivos = fijos (no theme-aware)**: resuelven la estética theme-independent (periódico, splash) sin
  romperla — un token semántico fliparía en dark.
- **La estética propia del satélite** (periódico) vive en tokens **locales del satélite**, no contamina el DS.
- **La página de crash y los fixtures se DECLARAN** (`raw-color-ok`), no se tokenizan: declarado ≠ arrastrado
  (queda auditado y el gate lo sanciona).

## Acceptance Criteria

- `check-raw-color` **falla CI** si hay un valor crudo de color (hex, `rgb/hsl` con números, arbitrary Tailwind
  `-[#…]`, o clase de paleta cruda) en el DS o en el código de un consumidor, fuera de un fichero de definición
  de tokens y sin declarar `raw-color-ok`.
- El gate **exime** las líneas que DEFINEN un custom property (`--x: valor`), los ficheros de definición de
  tokens, los comentarios y `rgb(var(--token))` (uso de token con alpha).
- El gate corre en `npm run coverage` (DS) **y** `npm run governance` (rutas de consumidor) → barrido total.
- La **capa de primitivos** (`--color-black/white`, `--color-brand-google-*`, `--color-chart-1/2`) existe en
  `tokens.css`, propagada a los consumidores; `check-freeze`/`check-contrast`/`check-drift` siguen verdes.
- **Cero cambio visual**: cada raw tokenizado mapea 1:1 al valor actual (Dashboard VRT no se mueve).
- Los charts pierden `forceDark`/`useTheme`/`useMemo` y sus colores vienen de tokens (siguen el tema por CSS).
- Ships con **test** de `check-raw-color` (detecta un raw, exime definición/comentario/declaración).

## Alignment

Implementa estas decisiones del norte de `design-propagation` (ADR-028):

- **Detección de la clase de error grep-catchable (build-now item 2)**: `check-raw-color` es exactamente el
  gate que el estándar nombra para el color crudo (frente a la clase semántica, que es revisión/allow-list).
- **Barrido total sobre consumidores (build-now item 2)**: el gate corre en rutas de consumidor vía
  `governance`, no solo el DS — completa el cierre de la deuda "el gate solo cubre el DS".
- **Capa de tokens por indirección (research de la estrategia)**: los primitivos (option tokens) son la capa
  base del patrón layered-tokens (Martin Fowler / Style Dictionary) que el research documentó — sin adoptar
  DTCG (sigue NON-GOAL diferido): son CSS custom properties, cero build, cero deps.
- **Propagación por el canal existente**: los primitivos viajan por `em-ui init` (el canal de tokens), sin
  generador ni push (invariante PULL de ADR-006/007/027 intacto).
- **No-goals respetados**: no DTCG, no generador, no re-plataforma, no se toca el contrato de un primitivo
  registrado (los charts/AuroraBackground son app/DS-own, no primitivos em-ui registrados).
