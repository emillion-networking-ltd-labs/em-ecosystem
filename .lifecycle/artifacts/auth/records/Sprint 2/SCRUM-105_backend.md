# Implementation Record: SCRUM-105 Account Self-Deletion + GDPR Compliance

## Summary

Implemented GDPR Article 17 (Right to Erasure) compliant account self-deletion: authenticated users delete their account via `DELETE /users/me` (password-confirmed for local accounts, JWT-only for OAuth), receive a confirmation email, then PII is atomically anonymized (tombstone pattern), sessions/tokens hard-deleted, and audit log metadata scrubbed. SUPERADMIN accounts are protected.

## Lessons Learned

- Prisma v7 nullable JSON columns require `Prisma.DbNull` (not plain `null`) when setting to database NULL in `updateMany`. This is a Prisma-specific gotcha that should be noted for future tickets involving JSON field manipulation.
- The plan's step-by-step dependency order (schema → enum → DTO → mail → service → controller → tests) again proved correct with no backtracking needed.
- Making `DeleteAccountDto.password` optional with service-level conditional logic (check `user.passwordHash` existence) was a clean pattern for handling both local and OAuth account types with a single DTO.
- The `$transaction` array approach (vs sequential callback) worked well for 5 independent operations that don't need intermediate results.
